# Palette PNG Web v0.1.2

原寸・色・透明度を保ちながらPNGをパレット形式に変換する静的Webアプリです。
画像はブラウザ内のWeb Workerで処理され、サーバーに送信されません。
解析サービス、外部フォント、CDN、APIキー、npmビルドは不要です。

## GitHub Pagesで公開（新しいリポジトリ）
1. GitHubに公開用リポジトリを作成します。
2. このフォルダの中身をリポジトリ直下にアップロードし、コミットします。
   `index.html` が直下にある配置にしてください。ZIP自体をアップロードするのではありません。
3. リポジトリの Settings → Pages を開きます。
4. Build and deployment の Source を Deploy from a branch にします。
5. Branch は main、フォルダは /(root) を選び、Save。
6. デプロイ完了後、Pagesに表示されるURLを開きます。
   通常は `https://ユーザー名.github.io/リポジトリ名/` です。

GitHub公式: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 既存の日記サイトの一部として配置
公開中のサイトの `apps/palette-png/` などに、このフォルダの中身を入れます。
既存サイトの index.html は置き換えないでください。
日記に `apps/palette-png/index.html` へのリンクを設置すれば利用できます。
全ファイルが相対パスなので、リポジトリ配下やサブフォルダでも動作します。

## ファイル構成
- index.html: 画面
- style.css: デザイン
- app.js: ファイル選択・操作・ダウンロード
- png-core.js: PNG変換・ZIP作成
- worker.js: バックグラウンド処理
- .nojekyll: GitHub Pagesの静的配信指定（リポジトリ直下に配置する場合）

原稿のサンプルは同梱していません。公開するのはアプリのファイルだけです。

## 使い方
1. PNGをドロップ、またはファイル選択。複数選択できます。
2. 「変換する」。小さくならない画像は初期設定でスキップします。
3. 各画像の「保存」、または「まとめてZIP保存」。
4. 保存後は一覧をクリアしてメモリを解放できます。

元画像への上書きはしません。出力名は `_palette.png` になります。
同じ出力名には連番を付けます。保存先はブラウザのダウンロード設定に従います。
停止すると処理中のWorkerを終了します。処理済み画像は保存できます。
ページを閉じると選択画像・結果は失われます。

## 変換の仕様
- PNGの圧縮データを直接読み書きします。Canvasによる色空間変換や再描画は使いません。
- RGBAの組み合わせが256種類以内なら、画素値を変えずに変換します。
- 1・2・4・8bitを自動選択。完全透明ピクセルのRGBも保持します。
- ICC・sRGB・ガンマ・色度・DPI・テキスト・EXIFのチャンクを保持します。
- ICCプロファイル付きのグレースケールPNG（透過あり・なし）は、色の見え方を保つため変換せずスキップします。パレットPNGにそのまま引き継げないグレースケール用ICCの不整合を防ぎます。RGB用ICCを持つカラーPNGは従来どおり変換できます。
- その他の付帯チャンクは引き継ぎません。
- 16bit/チャンネル、インターレースPNG、APNGは変換せずにスキップします。
- 1枚5,000万画素、入力256MB、展開データ256MBまで。
- 変換結果を保持できる合計は200MBまで。大量の原稿は分けて処理してください。
- 表示時のメモリ量を減らすツールではありません。
- ブラウザ標準のCompression Streams APIを使います。Mac版と圧縮率が異なることがあります。

新しいSafari・Chrome・Firefox等、CompressionStream / DecompressionStream / Worker対応環境が必要です。
ファイルをダブルクリックする file:// ではWorkerが動かないため、HTTP/HTTPSで開いてください。
ローカルで確認する場合は、このフォルダで `python3 -m http.server 8000` を実行し、
`http://localhost:8000/` を開く方法もあります（Pythonがある場合）。

## 検証
- 提供原稿3703×6222pxで全RGBA画素一致、ICCとDPI保持を確認。
- 2/3/4/5/16/17/256種類のパレット境界を確認。
- 白黒1bit、グレー、グレー＋透明度、RGB、RGBA、パレットを独立デコーダーで検証。
- 257種類、CRC破損を拒否。日本語名を含むZIPの整合性も検証。
- 変換ロジックはNode.jsのCompression StreamsとPillowで検証しました。
- v0.1.1では34件の合成画像による基本テスト（28件の全RGBA画素・寸法・ビット深度一致、6件の想定どおりの拒否）、メタデータ保持、日本語名28件のZIP整合性を再検証しました。
- ICC付きグレースケール／グレースケール＋透明度のスキップと、RGB用ICC付き画像の変換・ICC保持を回帰テストしました。
- 実ブラウザ上のUI・ファイル選択・停止／再開・ダウンロード操作、およびSafariは未検証です。この環境ではローカル検証ページへのブラウザアクセスが制限されています。
- 参考値：提供原稿は779,907 → 370,951バイト（Node.jsでの測定）。ブラウザにより結果は変動し得ます。
